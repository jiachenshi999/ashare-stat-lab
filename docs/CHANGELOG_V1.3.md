## 二·补 静默空图缺陷修复（V1.3.1，由用户截图反馈触发）

**现象**：用户截图显示 P2 页面三张卡片（行业 PE、行业 PB、行业年度收益热力图）纯白无内容，而上方 PE 曲线正常。

**定位**：不是 ECharts 故障。`industry.json` 约 4.4MB，`valuation.json` 仅 0.53MB；在 industry 尚未加载完成（或加载失败）时，9 处绘制函数执行 `if (!INDUSTRY) return;`，卡片就永久白着——**既不提示原因，也无法重试**。这是可用性缺陷，命中条件为"首屏/弱网/部署缺文件"。

**修复**：

1. 新增 `chartNotice(id, text)`：数据未就绪时在图表区内居中写明原因，不再返回空。
2. 9 处静默 `return` 全部替换为显式提示（行业数据提示含"约 4.4MB，首次加载需几秒"）。
3. 页面顶部新增数据状态横幅：加载中列出缺哪些序列；加载失败显示错误码 + 「重试」按钮。
4. `ensureIndustry` 增加并发保护（`industryLoading`）、错误捕获（`industryLoadError`）与 `retryIndustry()`。

**回归测试**：新增 `tests/check_p2_states.js`，用桩 DOM + 记录型 ECharts 断言三种状态：

| 场景 | 断言 | 结果 |
|---|---|---|
| 行业数据加载中 | 顶部横幅出现 + 行业 PE 图有占位文字 + 热力图有占位文字 | PASS |
| 加载失败（HTTP 500） | 失败横幅含错误码 + 重试按钮存在 | PASS |
| 数据齐全 | 无任何横幅、行业 PE 与超额热力图均有真实数据 | PASS |

## 六、V1.3.3 —— 前端数据瘦身（2026-11-23）

**动机**：`industry.json` 4.42MB 是 P2 首屏加载慢与"空图窗口"的物理原因。

**做法**（`backend/stage26_slim.py`，只改前端副本，不动统计口径）：
1. 删除前端从未使用的 `amount` 数组（31 行业 × 约 6500 日 = 144,491 个点）；
2. 价格 / PE / PB / 股息率统一保留 2 位小数（原值精度 ≤ 4 位）；
3. `valuation.json` 的 PE 同口径处理，null 保留以维持日期对齐；
4. 瘦身前把全量数据备份到 `data/backup/`（已加入 .gitignore）。

**结果**：

| 文件 | 瘦身前 | 瘦身后 | 降幅 |
| --- | --- | --- | --- |
| `data/industry.json` | 4.42 MB | **2.87 MB** | **-35.1%** |
| `data/valuation.json` | 0.53 MB | 0.48 MB | -9.7% |

**一致性校验**（瘦身前保存基线，瘦身后逐项对比 31 个行业）：
- 各行业年度价格收益最大偏差 **0.000000 个百分点**；
- PE / PB / 股息率 / 最新收盘 最大偏差 0.000000；
- 结论：**统计口径与页面数值完全未变**，只是删了未使用字段并截断冗余精度。

**验证**：`node --check` 通过、`render_check.js` 16 组合全 ok、`check_p2_states.js` PASS。
